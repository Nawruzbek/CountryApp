# Функциональные требования

## Актеры системы
- **Пользователь (Admin)** — авторизованный пользователь, имеющий доступ ко всем функциям.

## Варианты использования (Use Cases)

### 1. Аутентификация (Login)
**Описание:** Пользователь вводит логин и пароль для доступа к системе.
**Предусловие:** Система запущена.
**Постусловие:** Пользователь авторизован и получает доступ к меню.
**Альтернативный поток:** При неверных credentials — отказ в доступе.

### 2. Управление странами (Manage Countries)

#### 2.1. Добавление страны (Add Country)
**Описание:** Пользователь вводит данные о стране и может добавить регионы.
**Предусловие:** Пользователь авторизован.
**Постусловие:** Страна сохранена в БД.

#### 2.2. Просмотр всех стран (List Countries)
**Описание:** Отображение всех стран в виде таблицы.

#### 2.3. Удаление страны (Delete Country)
**Описание:** Удаление страны и всех её регионов (каскадно).

#### 2.4. Просмотр статистики (Show Statistics)
**Описание:** Вывод:
- Общего населения всех стран
- Средней площади стран
- Самой населённой страны
- Общего количества регионов

### 3. Управление регионами (Manage Regions)

#### 3.1. Просмотр регионов страны
**Описание:** По ID страны показать все её регионы.

#### 3.2. Добавление региона
**Описание:** Привязка нового региона к существующей стране.

#### 3.3. Удаление региона
**Описание:** Удаление региона по его ID.

## Нефункциональные требования
- **Надёжность:** Корректная работа с БД, обработка ошибок ввода.
- **Производительность:** Мгновенный отклик на команды.
- **Сопровождаемость:** Модульная структура проекта (C, контроллеры, интерфейсы).
- **Удобство использования:** Меню с числовым вводом, подсказки.
